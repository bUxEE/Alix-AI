# Efficiency review — X-10: first external provider adapter (OpenAI)

Every feature records this before it counts as done.

Provenance of the figures. The hosted-model names and prices below were read on **2026-10-07** from the vendor's pages
through a summarising fetch tool (URLs in `adapters/external/openai/doc.go`). The tool sometimes mislabels pages, and some
model names it returned (a "gpt-6" family, "gpt-5.6" variants) were not checked against a second source, so they are quoted
as **as summarised, not verified**. The binary sizes are **measured** on the Windows 11 dev box (Go, `CGO_ENABLED=0`,
default flags) and labelled **dev box**: neither emulated nor certified. **No latency, quality or live-cost figure exists
yet; live measurement is owed to X-H02** (real key, real money, human-gated). Nothing in this file is a measurement of a
provider call.

## Requirement
An opt-in hosted backend for the controller role of External and Hybrid mode, with the guarantee LocalAI v4.10.0 lacks:
a strict structured output the model cannot leave, so a `TaskProposal` always parses. Text, SSE streaming, tool-call
proposals (never executed), usage and cost in integer micro-units, health, capability discovery, bounded retry, and no
provider-native agent, memory, file search or stored response (`store:false`, function tools only). Disabled by default;
absent from a `noexternal` binary. Safety: the key comes only from the credential service; no response body reaches an
error, log or detail; fail closed on anything the contract cannot express.

## No-model / deterministic option
The adapter itself is deterministic code (request building, strict-schema conversion, SSE parsing, pricing arithmetic); no
model is involved in it. Whether a hosted model is needed at all is the operator's choice and the answer stays "no" for
every flow that has a deterministic or local path: Local mode is unchanged and the router (X-11) never sends the router,
reranker, VAD or embedder roles to a provider. Embeddings are implemented (`Embed`, off unless an embedding model is
configured) only so the contract is complete. Strict-schema conversion was done in code rather than by asking a model to
"reformat" the schema: it is exact, testable, and reversible (`StrictPlan.Restore`).

`config.go` cover only the five long-lived names marked *table*; any other model needs an operator price table or has no cost
and cannot be budgeted.

## Decision
Ship the adapter with **no default model** (the operator must name one, so a model or price change is never silent),
`gpt-5-nano` as the first tier to run through the routing corpus and `gpt-5-mini` as the expected cheapest passing tier;
larger tiers are rejected until a measured failure of the smaller ones (X-H02). Responses API chosen over Chat Completions
(the vendor's recommendation for new work; both support strict outputs; Chat Completions remains the fallback). Strict mode
is used for every schema constraint and every tool; a schema that cannot be converted is refused, never sent with strict off.
**TaskProposal and strict-mode limits:** the contract schema (`schemas/conversation/task-proposal.schema.json`) cannot be sent
as written (external `$ref`s, a union containing an open map, an `allOf` of conditionals, optional members). The schema the
controller actually sends is the compact one from `internal/dialogue` (closed objects). It converts, and the adapter strips
`maxItems`, `maxLength`, `minimum`, `maximum` (the two readings of the vendor page disagreed about bounds, so the
conservative one is used; local validation keeps every bound), makes each optional property nullable and required, and
restores the answer (nulls of optional members dropped) before it is returned. Both facts are covered by
`TestTaskProposalCompactSchemaPassesStrictLimits` and `TestTaskProposalContractSchemaIsRefusedNotDowngraded`. For the next task
(X-12, the extmode wiring): send the compact schema, validate the restored `JSON` against the model-authority schema as
before, and use `Generate`, not `GenerateStream`, for typed output (a schema that needed conversion cannot be streamed).

## Resource impact
Measured, dev box, `CGO_ENABLED=0 go build ./cmd/alixai` (default flags):

| Build | Size (bytes) |
|---|---|
| default (with `adapters/external/openai`) | 42,231,296 |
| `-tags noexternal` | 42,015,232 |
| difference | 216,064 (211 KiB, 0.51 %) |

The ADR-0022 bar (more than 2 MiB or 5 %, whichever is smaller) is **not** crossed, so one artifact ships and the `noexternal`
tag stays a build option. `go list -tags noexternal -deps ./cmd/alixai` contains neither `adapters/external` nor
`internal/credentials`; the default build contains both. The OS keystore backend (`internal/credentials/oskeyring`) is not
linked by this task.
Runtime: disabled, the cost is one package-level map assignment in `init` and nothing else (no goroutine, socket, file or
connection; no outbound traffic). Enabled, the adapter is stateless apart from an `http.Transport` with at most 2 idle
connections per host; per call it holds the request/response in memory (response cap 8 MiB, stream event cap 1 MiB, stream
cap 32 MiB) and streams without buffering the whole body. Storage: none. Power and per-call CPU: not measured (the
conversion and parsing are linear in the schema and answer size). Latency and cost of real calls: not measured, owed to
X-H02. Concurrency: bounded by the caller and by the budget reservation in X-09, not by the adapter.

## 4 GB profile impact
Preserves it. The external code adds about 0.5 % to the binary, nothing to resident memory while external mode is off, and
the local-only build (`noexternal`) removes it entirely. A hosted model removes the need for a local controller model on
hosts that cannot hold one, which is the reason Hybrid mode exists for small machines; the cost moves to network and money,
and to the data-egress policy (X-04), not to RAM.
