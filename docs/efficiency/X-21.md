# Efficiency review — X-21: Meta provider adapter (Model API and hosted Llama)

Every feature records this before it counts as done.

Provenance of the figures. The model names, prices, limits and the shutdown date below were read on **2026-10-08** from Meta's
developer documentation (`dev.meta.ai/docs`) and from search summaries of third-party articles, all through a summarising
fetch/search tool (URLs and caveats in `adapters/external/meta/doc.go`). The tool sometimes mislabels pages, so every name, price and
limit is quoted as **as summarised, not verified**, and the Llama API shutdown on 2026-07-06 rests on third-party summaries only. The
adapter-overhead numbers are **measured** on the Windows 11 dev box (Go, `CGO_ENABLED=0`, loopback, a fake that answers from memory)
and labelled **dev box**: neither emulated nor certified. **No provider latency, quality or live-cost figure exists yet; live
measurement is owed to X-H02** (real key, real money, human-gated). Nothing in this file is a measurement of a provider call.

## Requirement
A Meta backend for the controller role of External and Hybrid mode ("Meta Model API or an approved hosted Llama
endpoint"), built only on what is real and permitted: official API credentials, never a consumer product (4.1). Text, SSE streaming,
a JSON-schema constrained answer, tool-call proposals (never executed), usage and cost in integer micro-units, health, capability
discovery, bounded retry, and no provider-native agent, search, file, memory or server-tool feature. Disabled by default; absent from a
`noexternal` binary. Safety: the key comes only from the credential service (`Authorization: Bearer`, never a URL or a body); no
response body reaches an error, log or detail; fail closed on anything the contract cannot express. The profile's billing notice
states that Meta AI and a Meta account are not API access.

## No-model / deterministic option
The adapter is deterministic code (request building, SSE parsing, pricing arithmetic); no model is involved in it. Whether a hosted
model is needed at all stays the operator's choice and the answer is "no" for every flow with a deterministic or local path: Local
mode is unchanged and the router never sends the router, reranker, VAD or embedder roles to a provider (no `Embedder` is implemented
here). The schema is sent as the caller wrote it (checked for size, object root and internal references only) rather than converted by
a model or by a large subset converter, because the service accepts it as-is with `strict` off; the caller's own validation is unchanged.

## Decision
Ship one adapter with **two dialects over the Chat Completions wire format**, no default model (the operator names one, so a model or
price change is never silent), and **muse-spark-1.3 on the Model API as the shipped profile** because it is the only first-party,
official, permitted option that exists today: Meta's own Llama API preview is reported shut down (2026-07-06) and the Model API lists
no Llama model. Hosted Llama (`DialectOpenAICompat`) is the generic fallback the brief names, with no default host; llama-4-scout is
the first tier to measure on it (X-H02).
- **Structured output**: `response_format` json_schema without `strict`, declared `schema_best_effort`, tool arguments
  `strict_arguments=false`. Not claimed strict: Meta documents constrained decoding only for `strict:true` over a narrow subset, and a
  generic host guarantees nothing. Adopting strict for the Model API needs a schema converter and a live check (X-H02).
- **Tool choice**: the Model API accepts only `auto`; `required` is sent as auto and enforced on the answer, `none` leaves the tools out.
- **Rejected**: the Responses and Messages protocols (a second wire format for no gain); a Bedrock adapter (not OpenAI-compatible);
  scraping or reusing a consumer Meta AI session (forbidden by 4.1); a default hosted-Llama host; the contributor tier by default;
  vendor SDKs (they would change `go.mod` and bypass the egress dialer and route guard).
- Duplication to remove later: the HTTP call scaffolding (`client.go`, `errors.go`) is a near copy of the other two adapters', because
  `adapters/external` holds only the SSE reader and the retry policy; a fourth adapter would justify moving it there.
- **Live risks that fixtures cannot show (X-H02):** whether `max_completion_tokens` and `stream_options` are accepted exactly as
  documented; the Model API's real output cap and tool maximum (the 32,768 and 32 here are conservative defaults); whether
  `finish_reason` ever takes a value outside stop/length/tool_calls/content_filter on a host (an unknown value is rejected, not
  guessed); that the model list route exists for `CheckModel`; the host-specific names of Llama models; per-host prices and limits.

## Resource impact
Measured, dev box, loopback, a fake that answers from memory (`TestAdapterOverheadLoopback`, `go test -v -run TestAdapterOverheadLoopback
./adapters/external/meta/`, three runs): one typed-proposal call (request build, loopback HTTP round trip, decode, pricing) takes
**4.1 to 4.3 ms, about 20 to 22 KB and 227 allocations**; most of the time is the loopback round trip and the egress dialer's
connection handling, not the adapter's own work. The 60 conformance runs (30 checks, Model API and hosted-Llama dialects) against the
fixtures take about 4.7 s, almost all of it the deliberate stall checks (300 ms deadlines).
Runtime: disabled, the cost is nothing beyond the compiled-in package (no `init`, goroutine, socket, file or connection; no outbound
traffic; the profile JSON is a 4 KB embedded byte slice). Enabled, the adapter is stateless apart from an `http.Transport`; per call it
holds the request/response in memory (response cap 8 MiB, stream event cap 1 MiB, stream cap 32 MiB) and streams without buffering the
whole body. Storage: none. Binary size with and without this package: not measured (`internal/cli/providers_external.go` is outside this
task's write scope, so the package is not yet linked into `cmd/alixai`; X-26 adds the case). Power: not measured.

## 4 GB profile impact
Preserves it. Nothing here loads a model or starts a service; the adapter is off by default and absent from a `noexternal` build, a
Lite or 4 GB deployment runs Local mode exactly as before, and the code adds no resident memory when disabled. External mode moves
inference off the host, so the per-request footprint on the host is a few tens of KB plus the open connection.
