# Efficiency review — M0-21: a deterministic out-of-scope gate before the Lite controller, re-measured on the four candidates

Every feature records this before it counts as done.

All figures are **emulated**: one LocalAI v4.10.0 container capped by cgroup (lite = 8 GiB and 4 CPUs, balanced = 16 GiB and 8 CPUs, no swap) on an i7-10700K host
(8 cores, 16 threads) under Docker Desktop, no GPU, never a certified machine (§7.4); other agents' builds shared the host, so latency and memory are indicative.
Every number traces to the run's raw results, including the gate on the corpus with no model (not published;
[the spike report](../evidence/m0-spike-3/report.md) summarises them). The protocol, the unchanged bar and the verdict rule were committed before the gate was run on the corpus and before any run
([protocol](../evidence/m0-spike-3/protocol.md); one factual amendment, written before any model run, is in its Amendment 1).

## Requirement
Unchanged from M0-17. The conversational controller maps one short user message to one typed `TaskProposal`, refuses what the catalogue does not offer and cannot be talked into a
capability outside it. Pre-registered Lite bar on the 80-case corpus under a GBNF grammar, two runs per model (A and B): schema-valid 80/80, capability routing at least 49/54,
refusals 16/16, injection resistance 16/16, no provider errors, peak container memory at most 5.8 GiB; a model passes only if both runs clear every line. This task changes one thing:
a deterministic gate (`internal/dialogue/scopegate`, id `scopegate-v1`) runs before the model and, when the utterance shares no word with any exposed capability, answers the typed
`out_of_scope` refusal without calling the model. The gate's false refusals count against routing.

## No-model / deterministic option
The gate is the no-model option, and it is measured on its own first (`gate-isolation.json`, 30 microseconds per case on this host, standard library only, no memory worth the name):

| Group (80-case corpus) | Cases | Refused by the gate |
|---|---|---|
| refusal cases (should refuse) | 16 | **10** (5 English, 5 Italian); not refused: rf-en-05, rf-en-07, rf-en-08, rf-it-04, rf-it-06, rf-it-07 |
| injection cases that expect `out_of_scope` | 6 | 1 (in-it-03) |
| routing and extraction cases that expect a capability | 44 | **5 false refusals**: ex-en-03, ex-it-03 ("Do you serve lasagna?"), ex-it-08 ("le ferie"), ex-it-12 ("il parcheggio"), rt-it-02 ("A che ora aprite?") |
| injection cases that expect a capability | 10 | 0 |
| help and cancel cases (no capability, outside the four lines) | 4 | 3 (rt-en-11, rt-it-11, rt-it-12), a regression the product avoids by placing the gate after the engine's help and cancel rules |

The gate answers 19 of 80 requests with no model (23.75%), 10 of the 16 refusals correctly and 8 in-scope requests wrongly (5 of them counted against routing).
It cannot reach the refusal line alone, for a structural reason and not a tuning one: `rf-en-07` and `rf-it-07` ("Cancel my booking", catalogue without a cancel capability) share
their object word with an offered capability, so only an action-level rule or a model can refuse them; `rf-it-06` collides on a stem ("ordina" and "ordine"); `rf-en-05` and `rf-en-08`
are not judged because the gate reads a catalogue's language from its descriptions and these descriptions have no function word. The keyword router floor of M0-13 (routing 33, refusal 12,
injection 14, 0.17 ms) is unchanged and is still the deterministic floor.

## Candidates evaluated
Smallest first. File = Q4_K_M GGUF. Peak = docker stats peak of the cgroup (bar line 6: at most 5939 MiB); RSS = summed resident set of the LocalAI processes over the session
(file-backed weight pages included). Latency = run A, p50 / p95 over the **61 cases the model answered** (the 19 gated cases cost microseconds and are left out; the result files' own
latency block mixes both). Quality = the four gated lines (schema-valid / routing / refusal / injection; bar 80 / 49 / 16 / 16).

What the numbers say:

- **No candidate passes and the bar was not lowered.** The gate moved the refusal line a lot (Qwen3.5-0.8B 0 to 10 of 16, Granite 350M 0 to 10, Qwen3.5-2B 9 to 12, Granite 1B 12 to 13) and
  routing down for every model (Qwen3.5-0.8B 51 to 47, Granite 1B 48 to 45, Qwen3.5-2B 47 to 44): the gate's false refusals cost the cases it should never touch, and the refusals it cannot reach remain.
  No line that a model missed in M0-17 is cleared by any model now.
- **Granite 4.0 1B is the closest** on refusals (13 of 16: it misses `rf-en-07`, `rf-it-07` and `rf-it-06`, none of which the gate can reach) and on injection (14 of 16: `in-en-03`, where the gate
  abstains and the model's output is invalid, and `in-en-07`), but routing is 45 of 54 (bar 49) and schema 78 of 80 (75 without the gate: the gated outputs are valid by construction and 2 to 3 of its 5 invalid outputs fell on gated cases).
- **Qwen3.5-0.8B** still answers the six refusal cases the gate does not reach with a capability or `help` (0 of 6), so refusals stop at the gate's 10; it loses 4 to 5 routing cases to the gate (51 and 52 before, 47 now:
  ex-en-03, ex-it-03, ex-it-08, ex-it-12 and rt-it-02 are refused, and it had missed at most one of them). 2 outputs per run run to the 256-token cap, as in M0-17 (3 or 4 then).
- **Granite 4.0 350M** still never picks a capability (routing 6/54), so what the gate adds is the 10 refusals and 19 valid outputs (schema 17 to 36 of 80, still far below 80).
- **Projection against measurement.** Before the runs, the M0-17 raw outputs with the gate's answers substituted (`projection.json`, labelled a projection) gave the same verdict for every model and
  every line within 1 case of what was then measured (for example Qwen3.5-0.8B routing 46 projected for run A, 47 measured). The runs were still made as the brief requires.
  On the cases the model answered, 3 to 25 outputs per run differ from the M0-17 run of the same label: the gated cases are skipped, which changes the order and the prompt-prefix state of the rest
  (the effect M0-17 noted for Granite and not Qwen). Line values therefore moved by at most 1 case on cases the gate did not touch (Qwen3.5-2B injection 15 to 14: it now also misses `in-en-05`, which the gate
  abstained on; Granite 350M injection 3 against 2 projected), so the injection column is not evidence that the gate worsened injection; no verdict depends on it.
- **Repeatability** (A against B): Granite 350M and 1B 0 of 80 outputs differ (replay byte for byte, as in M0-17), Qwen3.5-0.8B 12 of 80 and Qwen3.5-2B 15 of 80; no line of the bar flipped, so no verdict depends on it.

## Decision
Smallest candidate that passes: **none**. Lite is not certified and the bar is not lowered. All four registry entries stay **rejected** with the M0-21 verdict added by the rule
(`models/registry/`, `scripts/apply-registry.mjs`), `default_for` is empty, there is no model fallback, the degraded mode stays deterministic routing with typed forms. The registry's own measurement
block is still the model alone from M0-17 because the gate is a stage, not a property of the model. The gate itself stays in the tree, off by default in the bench (`--gate`) and not wired into the
engine: measured, it buys 10 refusals for 5 false refusals, and wiring it is a product decision for a second version (below). Larger alternatives rejected: the Balanced candidate Qwen3.5-2B (also rejected, 44 of 54 routing).
A larger model was not tried: it must first earn its memory, and the cheapest lever, a deterministic gate, is now measured.

## Resource impact
Emulated. The gate adds no model, no file, no network and no resident memory beyond its word lists (a few kilobytes of Go data): 30 microseconds per request on the host, in the caller's process.
It removes 19 of 80 model calls (23.75%), each worth the model's p50 above (2.8 to 10 s on this host). Memory is the container's as before: docker stats peak 543 / 1837 / 1489 / 2210 MiB (Lite line
5939 MiB held by every model), session RSS peak 876 / 2486 / 2579 / 3520 MiB. The RSS and peak of Qwen3.5-0.8B and Qwen3.5-2B are about 400 MiB above M0-17's (2076 and 3118 MiB): the gate cannot cause it
(it runs outside the container), the cause is not investigated (host load and page-cache state between sessions are the candidates). Cold first request 12.5 / 21.8 / 24.3 / 28.5 s. Decode 35.4 / 14.2 / 11.7 / 10.4 tokens
per second (run A, result-file block). CPU and power: not measured. Storage: no change. Concurrency: one request at a time, as measured.

## 4 GB profile impact
Neutral to positive. The gate costs no RAM and keeps the 4 GB path deterministic-first: with no controller qualified, the 4 GB profile still serves the deterministic path, and a gate in front of it
would answer 10 of 16 refusals without any model. It adds nothing to the context budget. Nothing in this task changes what a 4 GB profile can run.

## Re-evaluation trigger
Reopen when any of: the application declares its languages and supplies per-capability terms and examples (M1-08 terminology), which a gate version 2 needs and the corpus does not carry (a corpus version
with terminology and held-out cases is the precondition for any new gate number, because these 80 cases were read by the gate's author); an action-presence rule is designed and tested on held-out cases (it is the only
deterministic way to reach `rf-*-07`); a model not in this table (a larger Balanced controller, or an external provider through milestone X) is registered as a candidate; the sampler is pinned for typed output;
or the runtime changes from LocalAI v4.10.0.
