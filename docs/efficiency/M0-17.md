# Efficiency review — M0-17: controller re-measurement with a grammar-constrained gateway and bench-prompt-v1

Every feature records this before it counts as done.

All figures are **emulated**: one LocalAI v4.10.0 container capped by cgroup (lite = 8 GiB and 4 CPUs, balanced = 16 GiB and 8 CPUs, no swap)
on an i7-10700K host (8 cores, 16 threads) under Docker Desktop, no GPU, never a certified machine (§7.4); other agents' builds shared the host, so
latency is indicative. Every number traces to the run's raw results (not published); [the spike report](../evidence/m0-spike-2/report.md) summarises them.
The protocol, the pass bar and the verdict rule were committed before the first run ([protocol](../evidence/m0-spike-2/protocol.md), commit 4ad3442).

## Requirement
Unchanged from M0-13. The conversational controller maps one short user message to one typed `TaskProposal` (capability id from the catalogue or null,
intent, fields), refuses what the catalogue does not offer and cannot be talked into a capability outside it. Pre-registered Lite bar on the 80-case
corpus under a GBNF grammar, two runs per model (A and B): schema-valid 80/80, capability routing at least 49/54, refusals 16/16, injection resistance
16/16, no provider errors, peak container memory at most 5.8 GiB; a model passes only if both runs clear every line (decoding is not repeatable at
temperature 0 for some models, M0-15). This task changes the two defects of the M0-13 experiment and nothing else: the gateway now constrains with a
grammar (F1, F2) and `bench-prompt-v1` defines every intent (F3).

## No-model / deterministic option
Not re-run: the keyword router of M0-13 (routing 33/54, refusal 12/16, injection 14/16, 0.17 ms per case,
no memory) is unchanged and is still the floor. It does not pass, and it still beats Granite 350M on every line. The deterministic path (typed forms
plus rules) stays what Lite serves; the registry's `degraded_mode: deterministic-routing` is the fallback for every controller entry.
The output grammar itself is a no-model measure and it works as designed: every run has `finish_reason stop` for all outputs except the 3 or 4 that
Qwen3.5-0.8B runs to the 256-token cap, no output is outside the grammar's shape, and every remaining schema failure is a rule a grammar cannot express
(a task with a null capability, `maxProperties`), which is why validation after decoding stays mandatory.

What the numbers say:

- **No candidate passes, again, and the bar was not lowered.** Prompt v1 and the grammar moved some lines a lot and the verdicts not at all.
  Routing: Granite 1B 37 to 48 of 54 (one short of 49) and Qwen 0.8B 52 to 51 and 52 (passes line 2, as in M0-13); the refusal line did not move for
  the small models. The best single line miss is Granite 1B routing 48/54, but it also misses schema (75/80), refusal (12/16) and injection (13/16).
- **Granite 350M** still never picks a capability: the intent labels are better (it now says `task`) but 61 of 80 outputs are `task` with
  `capability_id: null`, which the schema refuses. 17/80 valid is worse than M0-13's 55/80 because v0 let it write `help` with a null capability, which is valid.
- **Qwen3.5-0.8B** routes 51 to 52 of 54 and still never refuses (0/16): 13 refusal cases get a catalogue capability with intent `task`. 3 or 4 outputs
  (Italian cases) run to the 256-token cap and are not JSON; the gateway now turns that into a typed failure. Injection: 2 of 3 failures are
  `cancel` with `reservations.cancel`, the third a truncated output.
- **Granite 1B**: 12 of 16 refusals correct (2 answered `task` with a null capability, 2 `cancel` with a capability); 5 outputs are `task` with a null capability
  (schema invalid) and 3 of the injection misses are that same invalid shape.
- **Qwen3.5-2B**: schema 80/80, 9 of 16 refusals (4 answered `help`, 2 `cancel` with a capability, 1 `help` with a capability), routing 47/54 and one injection followed
  (`in-it-05`, a `reservations.cancel`). It is 2 routing cases and 7 refusal cases short, on a profile that is not Lite.
- **Repeatability** (A against B, identical requests in the same order, same container): Granite 350M 0 of 80 outputs differ, Granite 1B 0 of 80,
  Qwen3.5-0.8B 14 of 80 (2 strict-pass flips; run B was in the same cold session as run A), Qwen3.5-2B 18 of 80 (3 flips). No line of the bar flipped for any model, so
  no verdict depends on it. This is the opposite of what M0-15 saw with 5 identical single requests (Granite 350M 2 distinct outputs, Qwen3.5-0.8B 1): here the Granite models
  replay byte for byte and the Qwen models do not. The cause is not found and this task did not look for it; the debug probe shows two differences that are
  hypotheses only: llama.cpp reuses the cached prompt prefix between Granite requests (15 of 479 tokens evaluated on the second request) and re-evaluates the whole prompt for Qwen3.5
  (499 of 501), and LocalAI applies `presence_penalty 1.5` to the Qwen family unless the model definition sets it (the spike's does not). Seed: drawn at random by LocalAI at each model load, the harness sends none;
  sampler settings per model in `protocol.md` and `run-manifest.jsonl`. Neither a Granite nor a Qwen measurement here is claimed reproducible beyond what A against B shows.
- **Run discipline.** The first Qwen3.5-0.8B session lost its container after case 54 of run A (26 provider errors `unavailable`; the container vanished while the
  agent was paused, run B could not connect). That attempt is kept as `A-aborted` in the manifest and `bench check` passes on it; the model was re-measured as A and B
  in a new cold session, per the protocol's rule for provider errors that are not the model's.

## Decision
Smallest candidate that passes: **none**. Lite is not certified and the bar is not lowered. All four controller registry entries stay
**rejected** with the M0-17 measurements and verdicts recorded (`models/registry/`, by `scripts/apply-registry.mjs`, rule only), `default_for` is empty, there
is no model fallback. Rejected here means rejected on `bench-prompt-v1` with this grammar and this sampler configuration, not for all prompts.
The gateway change stands regardless of the verdict: the controller request is constrained by a grammar (`proposeBuildChat`), validated after decoding
and an answer cut at the token cap is a typed `schema_invalid` (stage `truncated`), never a partial proposal (`proposeDecode`).
Larger models were not tried: a larger model must first earn its memory against the 5.8 GiB line, and the two cheapest levers (grammar, intent definitions)
are now exhausted for these four candidates.

## Resource impact
Emulated. Prompt v1 costs 192 more input tokens per request than v0 (309 to 501 for Granite, 326 to 519 for Qwen), which is where the longer latency of the
small models comes from (Granite 350M p50 2.2 s to 2.9 s, Granite 1B 7.9 s to 8.5 s, Qwen 0.8B 7.2 s to 7.9 s, Qwen 2B 9.8 s to 8.8 s with a quieter host). Memory is unchanged within noise: docker stats peak 551 / 1456 / 1499 / 1810 MiB
(Lite bar line 6: 5939 MiB, held by every model), session RSS peak 864 / 2076 / 2540 / 3118 MiB (2B on the balanced profile). Cold first request 9.7 s / 22.1 s / 22.7 s / 25.8 s.
Decode 35.6 / 18.6 / 12.2 / 11.4 tokens per second. Storage: no change. Concurrency: one request at a time, as measured.
CPU and power: not measured. The gateway change adds one grammar string per request (mean 958 bytes, at most 1036, over the 80 corpus catalogues).

## 4 GB profile impact
Neutral. Nothing in this task changes what a 4 GB profile can run: no controller qualified, so the 4 GB profile still serves the deterministic path. The
M0-15 projection (1650 MiB controller row) stays unmeasured under 4g because no model passed (M0-15 asked for that measurement only for a passing model).
The 192-token prompt growth stays inside the 4096-token context budget the profiles use; KV cache was not measured.

## Re-evaluation trigger
Reopen when any of: a model that is not in this table (a 1B to 2B class instruction model, or a router-sized classifier plus a grammar) is registered as a candidate;
the sampler is pinned for typed output (for example `presence_penalty 0` for the Qwen family) and the repeatability question of M0-15 is answered; the gateway moves to
`internal/dialogue` (M1-14) with a refusal path that does not depend on the model alone (a deterministic pre-check of out-of-scope requests against the catalogue);
or the runtime changes from LocalAI v4.10.0. The cheapest next experiment is not a larger model: Granite 1B is 1 routing case short, and every model that fails
refusals answers a refusal with `task` and a capability or `help`; a deterministic out-of-scope gate in front of the model (keyword router: refusal 12/16, injection 14/16) is the
no-model lever to measure first.
