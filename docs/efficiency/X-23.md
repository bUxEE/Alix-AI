# Efficiency review — X-23: connected-mode benchmark and provider comparison report

Every feature records this before it counts as done.

Labels. `recorded` is read from an artefact in the repository (shipped provider profiles, recorded wire fixtures replayed through the real adapters, M5-09 benchmark files);
`emulated` is produced by the latency-injecting loopback stub, inside the 4 GiB / 4 CPU / no-swap container (`tools/providercompare/run-4g.sh`), or computed from recorded
inputs on an assumed turn; `not measured` has no figure yet. **No provider was called**: no real key, no money, no external network (`--network none` in the container).
Real provider numbers are owed to X-H02. Everything below traces to [the benchmark report](../evidence/x-benchmarks/report.md) and its raw results (not published).

## Requirement
Acceptance criterion: the 4 GB / lightweight profile is benchmarked separately in Local and connected modes, from recorded fixtures and a latency-injecting stub, in the
same result envelope as `tools/bench`, and without using connected mode to hide that Local mode failed a hardware gate (§12). Deliverables: `go run ./tools/providercompare`
(capability, cost, latency, failure behaviour and the shared corpora across the four adapters), a connected-mode footprint run under the experimental 4 GB profile, and the report.

## No-model / deterministic option
This task contains no model. The stub plays the corpus's own expected answer, so the comparison measures wire fidelity (request accepted, reply decoded unchanged), the adapters'
failure mapping and cost arithmetic, never the quality of a hosted model: that column is `not measured` for every provider. A hosted-model quality run is a different, human-gated
task (X-H02: key, money, terms). The fixtures are the adapters' own `testdata` (copied, with a test that fails when a copy drifts), so no new recording was invented.

## Candidates evaluated
Smallest hosted tier of each provider first; prices are the recorded profile tables ("as summarised, not verified", X-19 to X-21); the cost of one assumed turn (1,500 in, 200 out)
is computed by the adapters (`emulated`); quality and provider latency are `not measured`. Adapter overhead is the per-call time against a stub with no injected delay (dev box,
Windows 11, Go, loopback, `emulated`): about 4 to 5 ms p50 and 5 to 7 ms p95 for all four, almost all of it the loopback round trip and the egress dialer.

Wire fidelity over the shared corpora (emulated): all four adapters carry routing-v0 (80 of 80), the 84 model-decided turns of conversation-v1 and the 35 answered RAG cases back
unchanged, with the excerpt present in the request body and outside the system instruction; the 15 RAG declines are decided locally and send nothing. Failure behaviour (recorded
fixtures): a rejected key and an exhausted quota are one request with no retry; a rate limit that names a wait is retried once; a 5xx and a dropped connection are not retried; a
provider-native tool, active media or a malformed body is refused as `schema_invalid`; no error text carries the upstream body or the key.

## Decision
Ship `tools/providercompare` as a deterministic harness plus a generated report, and report the footprint of the connected control-plane pieces on their own. The cheapest hosted
tier by arithmetic is OpenAI gpt-5-mini, Gemini flash-lite next; neither is claimed to pass anything. Rejected: running a hosted model or any external call to fill the quality
column (hard rule: no real key, no external network); presenting stub latency as provider latency (the injected delay is an input and is printed as one); merging connected and Local
figures (the report keeps them in separate sections with the Local verdicts quoted unchanged); a result envelope with `provider.name` other than `fake` for stub replays (the
schema ties `synthetic` to it, and the stub is synthetic); sampling memory as `docker-stats` (the figures come from the cgroup files inside the container, so they go in a sidecar
`footprint-4g.json` rather than in the envelope's `memory` block, which stays `sampled: false`).
Duplication to remove later: `benchcopy_*.go` are verbatim copies of `tools/bench` types and aggregation (package main there); `go run ./tools/bench check` is the drift test. A
shared package would need `tools/bench` to change, which is outside this task.

## Resource impact
Emulated, one container capped at 4 GiB, 4 CPUs, no swap, no network, one run of 80 sequential calls (routing-v0, the four adapters in turn) and 400 concurrent calls (8 workers),
each call delayed 120 ms plus up to 80 ms of injected jitter: 0 errors in 480 calls, 21 s wall clock including start-up. Per-call p50 / p95 / max: 182 / 202 / 212 ms sequential,
155 / 200 / 211 ms under load; the time AlixAI added to each sequential call (call time minus the delay injected into that very call) is 4.5 ms p50 and 15.4 ms p95. Memory (MiB): harness process resident set 16.0 at start, 18.0 at peak (Go heap 6.8,
61 goroutines); idle `alixai serve` beside it 40.5 to 40.7; whole container (cgroup, page cache included) 63.7 to 66.1, `memory.peak` 66.1; swap 0, `oom_kill` 0, `cpu.max` 400000 100000.
For reference the Windows dev box idle core is 23.1 MiB working set and 55.0 MiB private (M0-15, recorded, not a Linux RSS). Storage: 82 kB result file, 24 kB footprint file; the
fixtures are 41 small JSON files. CPU time, power, a loaded core (sessions, RAG, SQLite, audit) and any ARM64 figure: not measured. Dev-box test time: about 8 s for the package.

## 4 GB profile impact
Preserves it and advances nothing. The connected-mode pieces measured here are small (about 66 MiB of 4096 in the container, leaving about 4030 MiB free, far above the 1024 MiB headroom floor of §7.4), but
the figure excludes the operating system, SQLite and RAG working sets under load, the audit log and the host application, and a full `alixai serve` in External or Hybrid mode was
not run, so it is not the 4 GB profile's headroom. **It does not offset, reopen or change any Local-mode verdict**: M0-17, M0-21 and M5-09 stand (no Lite controller qualified, Lite
uncertified, the 4 GB profile not promoted, Qwen3.5-0.8B at 2047 to 2074 MiB against a 2048 MiB line), and nothing is certified. Connected mode only moves the model off the host;
it needs the network and a provider's terms and bill (§12).

## Re-evaluation trigger
The first live run (X-H02) with real keys: replace the `not measured` quality and provider-latency cells with recorded results from the same corpora and a real network; any change
of a provider's prices, models or API shape (the fixtures and profiles are then re-copied and the drift test fails first); a new provider adapter; `tools/bench` exporting its
envelope package (then drop `benchcopy_*.go`); a full `alixai serve` External or Hybrid composition being available to the footprint harness; or a real 4 GB or ARM64 host.
