# Efficiency review — X-19: Anthropic provider adapter

Every feature records this before it counts as done.

Provenance of the figures. The hosted-model names and prices below were read on **2026-10-08** from the vendor's pages through
a summarising fetch tool (URLs in `adapters/external/anthropic/doc.go`) and from the model table bundled with the build tooling
(cached 2026-09-25). The tool sometimes mislabels pages, so every name, price and limit is quoted as **as summarised, not
verified**. The adapter-overhead numbers are **measured** on the Windows 11 dev box (Go, `CGO_ENABLED=0`, loopback, a fake that
answers from memory) and labelled **dev box**: neither emulated nor certified. **No provider latency, quality or live-cost figure
exists yet; live measurement is owed to X-H02** (real key, real money, human-gated). Nothing in this file is a measurement of a
provider call.

## Requirement
A second hosted backend for the controller role of External and Hybrid mode, with the same guarantees as the first: a
schema-constrained structured output and strict tool arguments so a `TaskProposal` parses, text, SSE streaming, tool-use
proposals (never executed), usage and cost in integer micro-units, health, capability discovery, bounded retry, and no
provider-native agent, memory, file, batch or server-tool feature. Disabled by default; absent from a `noexternal` binary. Safety:
the key comes only from the credential service (header `x-api-key`, never a URL or a body); no response body reaches an error, log or
detail; fail closed on anything the contract cannot express. The provider profile's billing notice states that a Claude subscription
is not API access.

## No-model / deterministic option
The adapter is deterministic code (request building, schema subset conversion, SSE parsing, pricing arithmetic); no model is
involved in it. Whether a hosted model is needed at all stays the operator's choice and the answer is "no" for every flow with a
deterministic or local path: Local mode is unchanged and the router never sends the router, reranker, VAD or embedder roles to a
provider (Anthropic offers no embeddings endpoint, so no `Embedder` is implemented). The schema subset conversion is done in code,
not by asking a model to "reformat" the schema; unlike the first adapter it never changes the shape of an answer (optional
properties stay optional), so nothing has to be restored and streamed structured output stays possible.

## Decision
Ship the adapter with **no default model** (the operator names one, so a model or price change is never silent), claude-haiku-4-5
as the first tier to run through the routing corpus and the expected cheapest passing tier; larger tiers are rejected until a measured
failure of the smaller ones (X-H02).
- **Structured output**: `output_config.format` json_schema (GA, no beta header), not a forced tool call: the newest models answer
  400 to `tool_choice` any or tool, and a forced call only existed to get JSON back. Tools are always `strict: true`.
- **Required proposal**: sent as `any` where the model accepts it (haiku-4-5) and as `auto` otherwise; "required" is then enforced on
  the answer (a missing proposal is an error), so the guarantee callers rely on holds on every tier.
- **Schema**: converted to the documented subset in code (closed objects, bounds and `pattern` stripped, `oneOf` as `anyOf`, open
  maps, recursion and external references refused, 20 strict tools / 24 optional properties / 16 unions per request counted). A
  stripped keyword costs only a local rejection of a bad answer by the caller, whose validation is unchanged.
- **No thinking, effort or other feature is sent unless the operator sets `Effort`**; thinking blocks in an answer are ignored, never
  carried.
- Rejected: forced tool use for structured output (400 on the newest tiers); the vendor SDK (it would change `go.mod` and bypass the
  egress dialer and route guard); the server-side `fallbacks` parameter (a silent provider-side model switch, against the no-hidden-
  fallback rule); the Batches API (not a request/response path); a default model.
- Duplication to remove later: the HTTP call scaffolding (`client.go`, `errors.go`) is a near copy of the first adapter's because the
  shared helpers under `adapters/external` only hold the SSE reader and the retry policy; a third adapter would justify moving it there.
- **Live risks that fixtures cannot show (X-H02):** a multi-turn tool exchange with an always-thinking model is sent without the
  earlier turn's thinking blocks (the single-step proposal pattern does not need them); the per-model limits and prices above; whether
  the API accepts `pattern` (it is stripped, so this does not matter for correctness).

## Resource impact
Measured, dev box, loopback, a fake that answers from memory (`TestAdapterOverheadLoopback`, `go test -v -run TestAdapterOverheadLoopback
./adapters/external/anthropic/`, three runs): one typed-proposal call (request build, schema conversion, HTTP round trip, decode,
pricing) takes **4.4 to 6.8 ms, about 23 KB and 256 allocations**; most of the time is the loopback round trip and the egress dialer's
connection handling, not the adapter's own work. The 30-check conformance run against the fixtures takes about 3 s, almost all of it
the deliberate stall checks (300 ms deadlines).
Runtime: disabled, the cost is nothing beyond the compiled-in package (no `init`, goroutine, socket, file or connection; no outbound
traffic; the profile JSON is a 4 KB embedded byte slice). Enabled, the adapter is stateless apart from an `http.Transport`; per call it
holds the request/response in memory (response cap 8 MiB, stream event cap 1 MiB, stream cap 32 MiB) and streams without buffering the
whole body. Storage: none. Binary size with and without this package: not measured (`internal/cli/providers_external.go` is outside this
task's write scope, so the package is not yet linked into `cmd/alixai`; the first adapter's measured cost was 211 KiB, 0.51 %).
Power: not measured.

## 4 GB profile impact
Preserves it. Nothing here loads a model or starts a service; the adapter is off by default and absent from a `noexternal` build, a
Lite or 4 GB deployment runs Local mode exactly as before, and the code adds no resident memory when disabled. External mode moves
inference off the host, so the per-request footprint on the host is a few tens of KB plus the open connection.
