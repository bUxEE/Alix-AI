# Efficiency review — M1-13: response verifier and deterministic response templates

Every feature records this before it counts as done.

All numbers below were measured on the Windows 11 dev box (Intel i7-10700K, 16 logical CPUs) with
Go 1.27, `CGO_ENABLED=0`, and are labelled **dev box**: they are not from a resource-limited
container, so they are neither **emulated** nor **certified**. Timings are the mean of
`go test -bench` runs (five runs of 2 s each; the ranges are over those runs), not percentiles.
Memory is the process's working set read from the OS (`GetProcessMemoryInfo`) in throwaway programs
that were not committed: a bare process that links only `pkg/contracts` and its generated
packages, the same plus `time/tzdata`, and the same plus `internal/verify` with a directive and a
response verified in a loop. The figures for a model-based checker are **estimates from sizes and
arithmetic, not measurements**: no model runs in this task, and each is labelled as such.

Repeat the measurements:

```
go test -bench . -benchmem -benchtime 2s -count 5 ./internal/verify/    # latency, allocations
go test -count=1 -cover ./internal/verify/                              # 306 passing tests and subtests (31 test functions), 91.3 % of statements
go test -run xxx -fuzz FuzzVerify -fuzztime 30s -fuzzminimizetime 0 ./internal/verify/
```

## Requirement
After the model verbalises a DialogueDirective or an ActionReceipt (§11.1 "verified natural
response"), decide whether the text may be shown, and speak only verified text (§13 "TTS begins
only after material facts are verified"):

- every fact named in `must_state` is stated, by value, after normalising numbers, dates, times,
  amounts and identifiers (English and Italian conventions);
- nothing is stated that the directive and receipt do not carry: no unknown number, date, time,
  amount, weekday or identifier (SEC-011, SEC-002);
- no completion claim without a committed receipt (SEC-011, SEC-047);
- no citation to a source the directive does not list (§12.5);
- when any check fails, the turn uses the deterministic template for the same directive, per act and
  language (en, it), so the user always gets the correct facts in plainer words; the same template
  is the response in degraded mode (§18, LLM unavailable) and when no model is installed.

Safety: the verdict is authoritative, so it must be deterministic and fail closed (§3 rules 5 and
14): an unusable directive is an error and never an OK, text with invisible characters is not
shown, and a template that does not itself verify is never returned.

## No-model / deterministic option
Chosen, and it is a complete answer, not a stand-in. What has to be checked is exact equality of
values the host already typed (the schema's canonical values exist so that the verifier can compare
numbers, dates, times, amounts and IDs "instead of matching prose", `schemas/actions/shared`), plus
the presence or absence of a handful of lexical classes. Code does that exactly and in
microseconds:

- **Values, not spellings.** A scanner and a small extractor reduce the response to atoms
  (numbers as exact decimal strings, dates as year/month/day, times, money as amount and currency,
  instants in UTC, identifiers verbatim) and compare them with the atoms of the directive. "14
  ottobre 2026", "14/10/2026" and "2026-10-14" are one atom; a datetime is compared in the zone the
  host displays it in. No floating point is involved anywhere (decimals are strings).
- **Everything the host and core authored is allowed**, found by running the same extractor over
  labels, choices, messages, source names and claims, so quoting them is never an invention.
- **Completion** is a lexicon of past participles and phrases in both languages with a
  clause-bounded negation rule ("was not booked", "non è stato prenotato"), checked against the
  receipt's status.
- **The template** is a message catalogue per language and act, and the same verifier checks every
  template before it is returned, so the two cannot drift apart.

Why no model, in one place:

1. **Authority.** Under rule 5 a model never owns facts or validation. A model-based checker could
   only be advisory: its verdict can be wrong in either direction, so a deterministic check would
   still have to stand behind it, and then the model adds cost and nothing else.
2. **The task is exact.** Whether "24" equals 24 or "10:30" equals 08:30Z in Europe/Rome is not a
   judgement call. Language models, and entailment models especially, are known to be unreliable
   with exact numerals, dates and IDs; a deterministic comparison is exact by construction.
3. **Latency sits in front of speech.** Verification is on the path to the first spoken word (§13).
   A model call would add a full prefill and decode before TTS may start.
4. **Determinism for audit and test.** The same directive and text always give the same verdict,
   so SEC-011 is an ordinary automated test and a fallback can be reproduced from a log.

What it cannot do, and where that is covered, is written in the package comment: whether a source
really supports a claim is the core's claim/source check (M2); whether a suggested action is
permitted is the policy gateway at prepare and commit; relative dates, ordinal words, roman
numerals, bare domain names, "one"/"un"/"uno"/"una"/"sei" as words, and completion verbs outside
the lexicon are not read. Each fails towards the template or is covered by another gate, and none
can make the verifier accept a wrong fact, because facts are compared by value.

## Decision
The deterministic verifier and templates, in `internal/verify`: `Verify` (verdict with typed
violations), `Render` (template per act and language), `Realise` (model text if it verifies, else
the template) and `Degraded` (template only). No model, no I/O, no goroutine, no configuration, no
state beyond a cache of loaded time zones; it imports only `pkg/contracts` (module map, tier 5).

Choices the plan left open, recorded for the ADR owner:

- **Embed the zone database** (`time/tzdata`, +0.40 MB stripped binary, measured) in this package.
  A datetime fact is compared in the IANA zone the host displays it in; without the embedded data a
  scratch container or a Windows service has no zones and the check could only guess or refuse. An
  unloadable zone is an error, never read as UTC. The cost is paid once per binary and the cache of
  loaded zones makes it free per turn.
- **Errors are not verdicts.** A directive or receipt the verifier cannot use (a `must_state` name
  that no fact carries, a malformed value, a receipt the directive does not name, an unsupported
  language) is a typed error (`schema_invalid`, `internal`, `validation_failed`) and never an OK.
  Languages other than `en` and `it` are an error: the caller chooses the language and the default.
- **A template is verified before it is returned.** A template that fails the verifier is a bug and
  is reported as an error (`internal`), never shown. The one exception is `receipt_missing` on an
  outcome whose receipt was not supplied: the template says the outcome is unconfirmed, which is
  true, while a model's text cannot be trusted without the receipt.
- **Invisible characters fail verification.** Zero-width characters, bidirectional overrides and the
  like display as nothing or reorder text, so what the verifier read is not what a reader sees.
- **A verbatim quotation of host or core text is not a completion claim** (a source claim "can be
  cancelled", a receipt message "was created but the email was not sent", a field label
  "Created:"), and a progressive form ("is being processed") is not either. Everything else in the
  lexicon is, and is allowed only against a committed receipt.
- **Boolean facts** without a display form are checked only for a plain yes or no; hosts that need
  more give the fact a display form.
- **No locale guessing:** the response language sets how separators and day/month order are read.
  An English "04/05/2026" is ambiguous and is accepted only when both readings are allowed;
  Italian reads it as the fourth of May. A number a model writes in the other locale's convention
  ("1,234" in Italian) is rejected, and the template shows the correct form.

Larger candidates rejected and why: see the table. A model is not needed for what this task has to
decide, and it could not carry the authority.

## Resource impact
All **dev box**; none of it from a resource-limited container.

| | Mean (five runs) | Allocation per call |
|---|---|---|
| `Verify`, 90-character confirmation, English | 37 to 44 us | 23.8 KB, 214 allocations |
| `Verify`, the same in Italian | 31 to 42 us | 22.4 KB, 200 allocations |
| `Verify`, outcome with a committed receipt | 29 to 41 us | 28.3 KB, 208 allocations |
| `Verify`, 2.2 KB answer | 208 to 248 us (about 9 MB/s) | 132 KB, 982 allocations |
| `Render`, English confirmation | 18 to 23 us | 19.1 KB, 141 allocations |
| `Realise` when verification fails (verify, render, verify the template) | 53 to 67 us | 39.2 KB, 362 allocations |

- **CPU.** Linear in the length of the text; a typical response is tens of microseconds, three to
  five orders of magnitude below the model call it follows. The work is an allowed-set build (the
  extractor over the directive's authored strings) plus one scan of the response. Hostile 16 KB
  inputs (a long run of separators, 5 000 citation markers, 16 000 brackets) take 1 to 30 ms per
  call; `TestPathologicalInputsStayLinear` asserts how the cost grows with the length, not a wall
  time, so it holds on a slow or loaded host. The text is capped at 16 KiB and a longer one fails
  closed. Two quadratic paths found while writing that test were fixed (a fingerprint hashed on
  every one of thousands of claims; violations computed after the cap).
- **RAM, steady.** Linking and initialising the package adds 0.7 MiB resident at process start
  (7.4 to 8.1 MiB) and 0.18 MiB of heap in use (the lexicon maps, five compiled expressions, the
  message catalogues). Per call there is 22 to 40 KB of short-lived garbage and nothing retained
  except the zone cache (one entry per zone name). Live heap stayed at 1.0 MiB through 201 000
  verifications. In a tight back-to-back loop the working set peaks at 19.7 MiB because the
  collector runs on a heap goal of a few MiB; a real turn calls it once.
- **Storage.** None: no table, no file, no cache on disk. The code is +0.79 MB of a stripped binary,
  the zone data +0.40 MB (3.13 MB against 1.93 MB for the bare process; the regular-expression and
  Unicode tables are shared with the rest of the service, so the increment inside the full binary
  is smaller).
- **Latency.** Added to a turn: 20 to 250 us for the verdict, 60 us more when the template is used.
  Speech waits for the verdict (§13) and loses nothing measurable.
- **Concurrency.** Every function is pure and goroutine-safe: no locks on the hot path, shared
  tables read-only, a `sync.Map` for the zone cache. No goroutine, timer or queue, so it needs no
  admission control and does not compete with background work (§3 rule 12).
- **Power.** Negligible: microseconds of CPU per turn, nothing at idle.

## 4 GB profile impact
Preserves it. The feature adds about 1 MiB resident and about 1.2 MB of binary, runs no model, no
service and no thread, and removes a reason to keep a second model resident for output checking. It
helps the 4 GB target a little: the verified path is what lets the smallest chat model be trusted
with phrasing at all, because a wrong sentence costs only plainer words, never a wrong fact.

## Re-evaluation trigger
- A third language, or a new canonical value kind in `schemas/actions/shared` (the extractor and
  templates need a pass).
- The fallback rate: if the fixed corpus of M1-GATE shows the template replacing the model's text
  often enough to hurt the product (the verifier is rejecting true text), re-open the false-positive
  list first (the lexicon, the identifier heuristics), not a model.
- Evidence that a completion verb outside the lexicon reached a user, or a new way to hide a number
  from the scan: add the case as a test, then extend the lexicon or the normaliser.
- A model release that makes an entailment checker both small and exact on numerals, for the
  semantic claim/source check in M2 only; never as the authority for facts (rule 5).
- If the binary-size budget of the 4 GB profile needs the 0.40 MB of zone data back: move the
  `time/tzdata` import to the composition root (a build tag), and keep the unloadable-zone error.
