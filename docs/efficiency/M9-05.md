# M9-05 efficiency review: EmbeddingGemma 2 (2026-10-08)

Requirement: a better or cheaper embedder than Granite Embedding 97M (384 dims, 390 MiB peak, p50 75 ms, emulated lite) for English and Italian retrieval.

- Smallest method first: the existing resident Granite 97M already serves it (the smallest-method-first rule); a larger model must earn its cost by measured gain.
- Candidate: EmbeddingGemma 2 text part (Q8_0 GGUF 310 MB on disk, 271M parameters, 768 dims, 8192 tokens). Weights alone are about 3x the Granite Q4_K_M file (105 MB); a measured RSS does not exist.
- Measured: nothing. The pinned LocalAI v4.10.0 llama.cpp (38a5b42d, 2026-09-15) lacks the `gemma-embedding2` architecture (llama.cpp PR #30054, merged 2026-10-06). LocalAI v4.11.0 and master are also too old. No container was run, no RAM, CPU, latency or power cost was incurred.
- Cost if adopted (estimates, not measurements): vector storage doubles (768 against 384 floats), every stored vector must be re-embedded (ADR 0032, M5-24); 256-dimension Matryoshka truncation would cut storage to two thirds of Granite's.
- Decision: keep Granite 97M as the default for Lite and Balanced; entry `egemma2-text-q8_0` recorded as an unloadable candidate. Re-evaluation trigger: a LocalAI release whose llama.cpp includes PR #30054. Rule and bar: [the verdict](../evidence/m9-embedding/verdict.md), section 4.
