# Efficiency review — X-20: Google Gemini provider adapter

Every feature records this before it counts as done.

Provenance of the figures. The hosted-model names, limits and prices below were read on **2026-10-08** from the vendor's pages
through a summarising fetch tool (URLs in `adapters/external/gemini/doc.go`). The tool sometimes mislabels pages (two of them came
back in the vocabulary of a newer API and were not used), so every name, price and limit is quoted as **as summarised, not
verified**. The adapter-overhead numbers are **measured** on the Windows 11 dev box (Go, `CGO_ENABLED=0`, loopback, a fake that
answers from memory) and labelled **dev box**: neither emulated nor certified. **No provider latency, quality or live-cost figure
exists yet; live measurement is owed to X-H02** (real key or OAuth consent, real money, human-gated). Nothing in this file is a
measurement of a provider call.

## Requirement
A third hosted backend for the controller role of External and Hybrid mode, with the same guarantees as the first two: a
schema-constrained structured output and constrained function arguments so a `TaskProposal` parses, text, SSE streaming,
function-call proposals (never executed), usage and cost in integer micro-units, health, capability discovery, bounded retry,
and no provider-native grounding, code execution, file search, cached content or other server-side feature. It is the adapter
that exercises the OAuth-first preference with a real provider: an API key and Google OAuth (through the shared engine) are both
supported and the account chooses per connection. Disabled by default; absent from a `noexternal` binary. Safety: the credential
comes only from the credential service or the OAuth engine (header only, never a URL or a body); no response body reaches an
error, log or detail; fail closed on anything the contract cannot express. The profile's billing notice states that Gemini API
access is tied to a Google Cloud project's quota and billing and that a consumer subscription is not API access.

## No-model / deterministic option
The adapter is deterministic code (request building, schema subset conversion, SSE parsing, pricing arithmetic); no model is
involved in it. Whether a hosted model is needed at all stays the operator's choice and the answer is "no" for every flow with a
deterministic or local path: Local mode is unchanged and the router never sends the router, reranker, VAD or embedder roles to a
provider (no `Embedder` is implemented here). The schema subset conversion is done in code, not by asking a model to "reformat"
the schema; it inlines references and never changes the shape of an answer (optional properties stay optional), so nothing has to
be restored and streamed structured output stays possible.

## Decision
Ship the adapter with **no default model** (the operator names one, so a model or price change is never silent),
gemini-3.5-flash-lite as the profile's model and the first tier to run through the routing corpus; larger tiers are rejected until
a measured failure of the smaller ones (X-H02).
- **Authentication**: both kinds supported, declared by `AuthSupport()` with OAuth first. The adapter does not
  import the OAuth engine (module map); it takes a `TokenSource` that the composition root wraps around `Engine.Token`
  (`oauth_engine_test.go` proves the wrapper fits and that the exported endpoints and scopes build a valid engine config). The
  first release path stays the manual key until live consent is verified. The scope requested is `cloud-platform`, the one the
  vendor names for calling the API; it is broad, the page names no narrower scope for `generateContent`, and the consent-screen
  requirements (External user type, test users while unverified, scope verification for production) are recorded with their date
  in `doc.go` and surfaced by `OAuthConsentNotes()`.
- **Structured output** is `responseMimeType` plus `responseJsonSchema` (full JSON Schema), not a forced function call; tool
  arguments use `parametersJsonSchema`. Schemas are converted in code to the documented subset (closed objects, references
  inlined, `const` as `enum`, `oneOf` as `anyOf`, lengths, `pattern` and exclusive bounds stripped, open maps, recursion, external
  references and `allOf` refused). A stripped keyword costs only a local rejection of a bad answer by the caller, whose validation
  is unchanged.
- **Tool mode**: required is `ANY`, cancellation `NONE`, otherwise `VALIDATED`; the profile declares strict arguments on that
  basis. Structured output together with tools is refused rather than sent.
- **No thinking, safety or other setting is sent**; thought parts in an answer are ignored, never carried.
- Rejected: the vendor SDK (it would change `go.mod` and bypass the egress dialer and route guard); the `?key=` query parameter
  (a secret in a URL); the newer Interactions API (the contract is request and response, and its pages were not usable as a wire
  reference); the free tier; a default model.
- Duplication to remove later: the HTTP call scaffolding (`client.go`, `errors.go`, the route guard) is a near copy of the second
  adapter's, which was a near copy of the first. This is now the third copy, so **moving it into `adapters/external` is the
  follow-up** (a small `external.Transport` with the route guard, credential header hook, retry loop and error envelope); it is out
  of this task's write scope.
- **Live risks that fixtures cannot show (X-H02):** the field names `responseJsonSchema` and `parametersJsonSchema` and the
  `VALIDATED` mode on the chosen model (from memory of the API, not read in the fetched excerpts); thought-signature handling on
  the newest models (a lost signature after a restart may be a 400 on a multi-turn tool exchange; no skip value is documented);
  the narrowest OAuth scope and whether `x-goog-user-project` is required with a token; the real 429 shapes and how a daily quota
  differs from a rate limit; the per-model limits and prices above.

## Resource impact
Measured, dev box, loopback, a fake that answers from memory (`TestAdapterOverheadLoopback`, `go test -v -run
TestAdapterOverheadLoopback ./adapters/external/gemini/`, three runs): one typed-proposal call (request build, schema conversion,
HTTP round trip, decode, pricing) takes **4.4 to 4.8 ms, about 26 KB and 276 allocations**; most of the time is the loopback round
trip and the egress dialer's connection handling, not the adapter's own work. The 30-check conformance run against the fixtures
takes about 2.4 s, almost all of it the deliberate stall checks (300 ms deadlines).
Runtime: disabled, the cost is nothing beyond the compiled-in package (no `init` that starts anything, no goroutine, socket, file or
connection; no outbound traffic; the profile JSON is a 4 KB embedded byte slice). Enabled, the adapter is stateless apart from an
`http.Transport` and a 256-entry map of thought signatures (at most 8 KiB each, bounded, in memory only); per call it holds the
request/response in memory (response cap 8 MiB, stream event cap 1 MiB, stream cap 32 MiB) and streams without buffering the whole
body. Storage: none. Binary size with and without this package: not measured (`internal/cli/providers_external.go` is outside this
task's write scope, so the package is not yet linked into `cmd/alixai`; X-26 adds the case). Power: not measured.

## 4 GB profile impact
Preserves it. Nothing here loads a model or starts a service; the adapter is off by default and absent from a `noexternal` build, a
Lite or 4 GB deployment runs Local mode exactly as before, and the code adds no resident memory when disabled. External mode moves
inference off the host, so the per-request footprint on the host is a few tens of KB plus the open connection.
